# Бот графіка відключень · с. Шрамківка, вул. Поштова, 5

Раз на ~10 хв GitHub Actions запускає `bot.py`. Скрипт бере графік із сайту Черкасиобленерго
(cabinet.cherkasyoblenergo.com, той самий запит, що робить пошук на сайті) і пише в Telegram:

- **закріплене «🗓 Графік відключень»** (сьогодні й завтра) — редагується щоразу;
- **«🗓 Оновлення графіка відключень»** — коли графік змінився або оприлюднили новий
  (статус при цьому перепубліковується прямо над повідомленням);
- **⏰ нагадування** за ~30 хв до відключення (вночі 23–7 без звуку).

Між запусками стан лежить у `state.json` (id закріпленого повідомлення, відомий графік, надіслані нагадування).

## Секрети (Settings → Secrets and variables → Actions)

| Назва | Що |
|---|---|
| `TG_TOKEN` | токен бота від @BotFather |
| `TG_CHAT` | id чату (особисті з ботом) або каналу (`-100…`) |
| `ABON_LS` | особовий рахунок адреси |

Секрети GitHub не показує в логах. У коді й `state.json` їх немає, тож репозиторій може бути публічним
(а публічному репозиторію хвилини Actions безкоштовні без ліміту).

## Як перевірити

- Вкладка **Actions → shramkivka-bot → Run workflow** — запуск вручну; лог покаже помилки.
- Локально без Telegram: `ABON_LS=… python bot.py --dry` (друкує повідомлення замість відправки).

## Відомі обмеження

- GitHub запускає cron із запізненням від кількох до ~20 хв, тому нагадування може прийти пізніше,
  а якщо запуск припав уже на час відключення — не прийти зовсім.
- Публічний репозиторій без активності 60 днів — GitHub вимикає cron. Скрипт раз на місяць змінює
  `state.json` (поле `alive`), тож коміт буде завжди.
- API сайту обленерго недокументоване, може змінитись. Якщо сайт мовчить понад 3 год, у статусі
  з'являється «⚠️ … графік може бути неактуальним».
